# RL Policy Training and Rolling Evaluation (Plan 3 of 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Train PPO long/short/flat policies on 15-minute decisions, with the detector output and the technique signals as inputs. Evaluate them on the 10 rolling test windows against the frozen baselines and pass criteria.

**Architecture:**
- A shared Numba per-minute transition kernel is extracted from `sim/core.py`. `core.simulate` and the new 256-env `rl/vec_env.py` both call it, so environment P&L equals engine P&L by construction. Tests check the match to 1e-9.
- A causal state store (`rl/state.py`) precomputes every 15-minute observation once per window.
- A minimal custom Torch PPO (`rl/ppo.py`) trains a 1D-conv or GRU encoder over the 32-step window carried in the observation. There is no recurrent hidden state.
- Baselines (`rl/baselines.py`) and evaluation (`rl/evaluation.py`) replay every comparator with the same window boundaries.

**Tech Stack:** Python 3.14 (venv_btcusdt), numpy, pandas, numba 0.68, torch 2.13+cu126 (RTX 3090). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-07-rl-trading-design.md` §4–§6. Design review: Codex, 2026-10-07 (summarised in the Contract section).

## Global Constraints

- Data cutoff 2026-01-01. 2026H1 is used once, only for policies that pass (Plan 4). Never inside a window.
- RL inputs start 2022-03-01. Data from 2020 to 2022-02 is used only for indicator warm-up and is never used for normalization statistics.
- Detector: frozen R2-44 w730_raw predictions via `sim.data.load_predictions`. No retraining.
- Windows: `sim.rolling.WINDOWS` (exactly 10, W01..W10). The test span is `[2023-09-01, 2026-01-01)`. The spec's "about 11" is infeasible, and this plan treats it as superseded.
- Reward (frozen, unchanged after results): `r = net_bps − 2·max(0, −net_bps) − 1·ΔMDD`.
- Nominal evaluation: 4 bps round trip, delay 1 minute, slippage 0, funding PESS, 1 unit, 1× bps.
- Training randomization is drawn once per episode:
  - cost ~ U(4, 12) bps round trip, so `fee_per_side = cost / 2`
  - slippage ~ U(0, 10) bps per market fill, adverse
  - delay: with probability 0.5 U{1..5} minutes, otherwise 1 minute. Measured latency is under one minute, so the empirical latency distribution maps to 1.
- No live orders, no authenticated exchange calls, no spot/DEX data.
- Every run records in its manifest and in `out/sim_registry.jsonl`: source, timestamp, data cutoff, frozen hypothesis, input hashes and n_trials.
  - Starting n_trials = 5125 + 128 + 16 + 8 = **5277**. This plan adds 8 candidate policies, for 5285.
- Frozen hypothesis (spec §8): "강화학습 정책이 롤링 테스트에서 C1_X·단일 기법 최고·지도학습 정책보다 비용 차감 후 우위".
- Never change definitions, thresholds or the reward after seeing validation or test results. A failure is reported as a failure.

## Contract (decisions the spec leaves open; frozen here before any training)

| # | Item | Decision |
|---|---|---|
| C1 | Action | Target position ∈ {flat=0, long=+1, short=−1} at decision T.<br>Same side: hold.<br>Flat: close at the T+delay open.<br>Opposite side: close and re-enter the opposite side at the same fill minute (`reentry="stop_and_reverse"`). |
| C2 | Costs | Round-trip cost c means `fee_per_side = c/2`. Market slippage s bps is applied adversely to every market entry and exit, so a reversal pays both sides. |
| C3 | Funding | Booked at the settlement minute on the size held at that minute, under the same PESS boundary rule as `costs.funding_events`. |
| C4 | Episode | 1,344 steps (2 weeks) with a random start such that the episode ends at or before `train_end`. The episode begins flat. Any open position is force-closed at the last minute's close, paying the exit fee and slippage. |
| C5 | Drawdown | MDD_t = running maximum over the episode of (peak cumulative net − cumulative net), using minute equity. ΔMDD = MDD_t − MDD_{t−1} per step (≥ 0). |
| C6 | Account state | Observed every step: position side, log1p(hold minutes), unrealized bps, MAE since entry, current drawdown, running MDD, steps to episode end / 1,344. Without these the reward is not Markov. |
| C7 | Missing detector | At T where M or L is NaN, or the prediction is older than 14 minutes, the action mask applies:<br>flat: only flat.<br>holding: hold or flat.<br>No new entry and no reversal. 2023-12-31 and 2025-12-31 are not interpolated. |
| C8 | Signals | 37 atomic catalog ids (K01–K30 and their parameter variants; excluding B1–B3, K10 grid and the OCO ids K06/K07/K14), as NONE/NATIVE event sides. Channels per id: `event_side`, `last_side`, `clip(log1p(age_min), 0, log1p(10080))/log1p(10080)`, `never_seen`.<br>OCO ids K06/K07/K14 get `proposal_active` and upper/lower distance in bps instead.<br>5-minute ids take the latest nonzero event in (T−15m, T]. 1h/4h ids take backward as-of `decision_time ≤ T`. No bfill. `ind_*` columns are not inputs. |
| C9 | Normalization | Continuous features only, using train-window mean/std (from 2022-03-01 to `train_end`). NaN becomes 0 after standardization, with a mask channel. Sides, masks, sin/cos and the account side are not standardized. |
| C10 | Network | Encoder over 32×15m steps (conv: 2 layers of kernel 3 with 64 channels, or GRU with hidden 64), concatenated with the static vector, then policy and value MLPs of 64. **No dropout:** a dropout mask differs between rollout and update, which breaks the PPO ratio. This is a spec deviation, ruled before training (see Rulings). |
| C11 | PPO | γ 0.999, λ_GAE 0.95, clip 0.2, value clip 0.2, rollout 128 × 256 envs, minibatch 4,096, 4 epochs, value coefficient 0.5, entropy 0.01, max grad norm 0.5, AdamW weight decay 1e-4, lr ∈ {1e-4, 3e-4}. |
| C12 | Stopping | Validate every 10 updates (327,680 transitions): deterministic argmax on the full validation window under nominal settings. Keep the best checkpoint by validation net. Stop after 5 evaluations without improvement or at 5,000,000 transitions. |
| C13 | Ensemble | 5 seeds by majority vote. A tie (2-2-1, or any tie for the top count) means flat. Criteria 1–5 and 7 use the ensemble. Criterion 6 uses the 5 per-seed results. |
| C14 | Supervised baseline | Labels at T: net bps of holding long, and of holding short, from the T+1 open to the T+1+240-minute open, minus 4 bps; flat = 0. Same encoder (conv, lr 3e-4) with MSE regression on the 2 action values. Purge the last 240 minutes before `val_start`. Act on the argmax; switch only if (best − current) ≥ 4 bps. Early stopping on validation net, same as C12. |
| C15 | Random baseline | Trade relocation Monte Carlo, 1,000 reps. Each rep keeps the RL ensemble's per-window trade count, sides and holding times, and places them at uniformly random non-overlapping starts inside the window. |
| C16 | Shuffled control | Within the train range, permute 1-day blocks of the exogenous state (detector, signals, market summaries) against the execution price path. Prices are not shuffled. Train the window-selected config with 20 seeds per window and evaluate on the real test windows. The null distribution is 20 stitched results.<br>**Budget gate:** this costs about 200 extra trainings; the user confirms it at Task 6. |
| C17 | Baseline ② | Recompute across all 152 frozen catalog combinations (Plan 2 with 128, R2-49b with 16, R2-50 with 8), excluding B1–B3. Pick the best validation net per window and replay its test window with the RL boundary rule (flat at the test start, force-closed at the test end). |
| C18 | Boundaries | Every comparator (① C1_X = K01 NONE NATIVE, ②, ③, ④, ⑤ always flat, ⑥ buy-and-hold entered at each test start) is replayed per test window: flat start, forced close, nominal costs. |
| C19 | HAC alpha | Intercept of the OLS regression of RL daily net on buy-and-hold daily net, with a Newey-West lag-7 95% CI. Criterion 3 requires lower bound > 0. |

## Review Focus

1. Settlement minute coinciding with a fill minute (entry, exit or reversal): funding must match `costs.funding_events` PESS exactly. Test it in Task 1.
2. A pending action whose delayed fill lands after the episode end, or inside a missing-detector day: it must be cancelled, and the forced close still happens at the last minute. Test it in Task 3.
3. Bar completeness at T for 1h/4h ids: a 1h bar closing at T+45m must not be visible at T. Test it in Task 2 with a prefix-invariance check.
4. Normalization fitted on a window whose train range contains extreme validation values: the statistics must not change when test or validation rows are perturbed. Test it in Task 2.
5. An all-flat policy: the reward is 0 every step, net 0, and evaluation reports "no trades" instead of crashing. `guard.check` must pass with a zero_reason. Test it in Task 7.
