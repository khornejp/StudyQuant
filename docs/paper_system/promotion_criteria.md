### 1. 목적과 의미

이 기준은 고정된 C1 paper 장부가 실전 **검토**를 시작할 최소 증거를 정한다. `PROMOTE`는 실주문 허가가 아니다. 실주문, API key 사용, 지갑, 결제, 인증 거래소 호출은 별도 사용자 결정과 AGENTS.md 변경 전까지 금지한다.

현재 상태는 “실전 후보 없음, C1/F3/E1/C4 shadow 기록”이다.

월은 달력 월로 계산한다. 각 판정 자료는 `[T0, 판정일)`이다. 중간 보고 수치를 보고 전략·문턱·비용·경계·주 장부를 바꾸지 않는다.

12개월과 24개월 두 번만 형식 검정한다. 각 시점에서 95% 양측 HAC CI의 하한을 사용한다. 한 시점의 단측 위양성 상한은 2.5%이고 Bonferroni 가족 위양성 상한은 5%다.

거래 수 하한은 두지 않는다. 0수익일도 정보이므로 모든 달력일을 회귀에 포함한다. 거래 수, 노출일, 방향별 수는 반드시 보고한다.

### 4. 판정 규칙

형식 판정일에 아래를 순서대로 적용한다.

1. 해결되지 않은 HALT 사유가 있으면 `HALT`다. 성과 판정은 보류한다.
2. 다음 세 조건을 모두 만족하면 `PROMOTE`다.
   - C1 PESS 알파의 95% HAC CI 하한이 0 bp/일보다 크다.
   - C1 PESS 누적 net이 0 bp보다 크다.
   - C1 일별 MTM을 신호 source로 귀속한 F3-source PESS 누적 net이 0 bp보다 크다. 판정일의 open position MTM도 포함한다.
3. T0 + 12개월에 하나라도 미달이면 `CONTINUE`다.
4. T0 + 24개월에 하나라도 미달이면 `RETIRE`다. 이는 알파가 0이라는 증명이 아니라 2년 관찰 예산에서 실전 검토 증거가 부족하다는 뜻이다.

OPT는 민감도 자료로만 보고하고 판정에 쓰지 않는다. 일별·누적 `PESS <= OPT` 불변식 위반은 장부 오류로 처리한다.

F3 약화 때문에 F3를 삭제하거나 E1/F3/C4로 갈아타지 않는다. 그런 변경은 새 전략, 새 문서, 새 T0가 필요하다.

### 5. HALT와 경고

다음 중 하나면 즉시 `HALT`한다.

- 의사결정·진입·청산·MTM·funding에 영향을 주는 1m kline, premium, LS ratio, funding 입력의 미복구 갭이 1건 이상이다.
- 필요한 입력이 없는데 신호 평가나 주문 모의를 진행했다. 허용 신호 누락은 0건이다.
- archive 재계산과 paper 사이 accepted/dropped signal, side, entry/exit timestamp 불일치가 1건 이상이다.
- C1/F3/E1/C4 어느 장부든 거래별 또는 일별 gross/cost/funding/net 절대 오차가 `1e-6 bp`를 초과한다.
- UTC 일일 archive 대조 가능 시점부터 24시간이 지나도 위 불일치가 해결되지 않는다.
- `PESS <= OPT`가 일별 또는 누적 경로에서 깨진다.

일시 수집 갭은 다음 영향 시점 전에 public REST/archive로 정확히 복구하고 원본·수정본·수신시각을 보존한 경우에만 허용한다. 보간은 금지한다. HALT 해제 전에는 불변 raw로 T0부터 전 장부를 다시 계산하고 exact parity를 확인한다.

성과 악화는 shadow 수집을 멈출 이유가 아니다. 다음은 `PERFORMANCE WARNING`으로 보고하되 전략과 평가 시계는 그대로 둔다.

- C1 trailing 92일 MDD가 `3,130.8 bp`를 초과한다. 이 값은 DEV 1,676개 92일 창의 p99다.
- F3 standalone 또는 C1 내 F3-source trailing 365일 net이 0 bp 이하가 된다. (DEV 참고 분포 p5/p50/p95 1,309.0/4,390.8/13,182.8 bp, 0 이하 비율 0.2138%)
- 183일 rolling 베타가 DEV p5/p95인 `-0.148/0.276` 밖으로 나간다.

### 7. 변경 절차

성과를 본 뒤 전략, 파라미터, 비용, funding 경계, 주 장부, B0, 주 지표, 판정일, CI 수준, 데이터 제외규칙을 바꾸면 기존 실험으로 주장할 수 없다. 변경 사유와 본 값을 기록하고 새 버전·새 T0로 시작한다.

frozen semantics로 되돌리는 구현 버그 수정은 전략 변경이 아니다. 이 경우:

1. 버그 발견시각, 영향 구간, 원인, 수정 diff/hash를 기록한다.
2. 불변 raw로 T0부터 전 기간을 재계산한다.
3. frozen batch 코드와 신호·거래 exact parity, 장부 `1e-6 bp` 이내를 확인한다.
4. parity가 성립하면 T0를 유지하고 운영 장애를 보고한다.
5. raw가 없어 정확한 재구성이 불가능하거나 parity가 성립하지 않으면 현재 실험은 HALT다. 성과 관련 규칙을 임의로 제외하지 말고 새 T0 여부를 사용자에게 결정받는다.

PROMOTE 뒤에도 자동 실주문 전환은 없다. 별도 실전 위험한도, 주문·슬리피지·장애·킬스위치 검토와 명시적 사용자 승인이 필요하다.
