## 3. 다시 테스트하기 전에 해야 할 것

1. **롱숏 비율 +5분 정렬로 4시간 모델 재학습.** 4시간 모델은 metrics 기반 피처 16개를 썼고, 모두 `create_time` 즉시 가용 가정(결함)이었다. `btcusdt_quant/metrics_source.py` 기본값은 이미 정정됐다. 피처 캐시를 다시 만들고 개발·1차 검증 전 fold를 재학습해야 한다. 근거: `out/k45_ls_ratio_timing_r2_35_20261006/REPORT.md` §4.
2. 15분 모델은 고정된 선택 피처에 metrics 피처가 없어 이 결함의 직접 영향이 없다. bookTicker 6개 피처는 이미 제외해 재학습했다(fold 347 이후 원래와 동일).
3. PatchTST는 영향 없음(입력이 OHLCV·거래 수·시간뿐).
4. 재학습 후 C3 조합을 개발·1차 검증 구간에서 다시 계산하고, C1과 같은 방식(알파·베타, 상위 거래 제외, 92일 창 분포)으로 비교한다. 최종 검증 구간은 이미 본 구간이므로 사후 참고로만 쓴다.
5. 모의에 넣으려면 실시간 입력이 더 필요하다: bookDepth 스트림(1분 집계), aggTrades 스트림(1분 집계), 1분 metrics 정렬. bookTicker는 쓰지 않는다(2024-04 이후 과거 데이터 없음).

## 4. 실행 시간 (측정값)과 속도 개선 후보

측정값 (2026-10-05, RTX 3090, 논리 코어 32):

| 작업 | 시간 |
|---|---|
| 15분 모델 롱 120분 전 fold(20–666) 재학습 | 약 55분 (fold당 1–6초, 학습 데이터 증가에 따라 증가) |
| 15분 모델 숏 60분 전 fold | 약 50–60분 |
| PatchTST 31 fold × 3 seed (3개월분) | 약 20–30분 (GPU) |
| 3개월 리허설 전체 (예측+평가) | 약 30–40분 |

개선 후보 (아직 검증 안 함):

- **증분 학습 대신 재사용:** 3일마다 fold가 바뀌어도 대부분 과거 fold 모델은 그대로다. 모의 운영에서는 새 fold 하나만 학습하면 된다(전체 재학습 불필요). 실시간 1회 학습 비용은 fold당 수 초(CatBoost)·수 분(PatchTST) 수준으로 예상.
- **CatBoost GPU 학습:** `task_type="GPU"`. 결과가 CPU와 달라지므로 기준 출력을 새로 만들어야 한다.
- **피처 캐시 고정:** 1분 피처를 일 단위 parquet로 미리 계산해 두고 fold마다 재계산하지 않는다.
- **PatchTST seed 병렬:** 3개 seed를 한 GPU에서 동시에 학습(메모리 여유 있음).
- **fold 병렬:** 서로 독립인 fold를 프로세스 여러 개로(CPU 8 상한 규칙 확인 필요).

## 5. 모의 시스템에 붙일 때 구조

설계 문서(`docs/superpowers/specs/2026-10-06-paper-trading-system-design.md`) §4의 전략 인터페이스에 모델 신호를 하나의 신호 소스로 추가한다. 학습은 별도 스케줄 작업(3일마다), 예측은 엔진 루프에서 최신 모델 파일을 읽는 방식. 모델 파일·피처 캐시 hash를 장부 meta에 기록한다. 새 장부(C3)는 새 시작일(T0)로 따로 센다 — 전환 기준 문서 §7.
